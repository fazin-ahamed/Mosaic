## Title

Attention scale / wgate / hc_head tensors appear corrupted in DeepSeek-V4-Flash-0731 (noise-like e8m0 scales, NaNs in bf16 wgate)

## Body

**Model:** `deepseek-ai/DeepSeek-V4-Flash-0731`
**Revision:** `7872f01b1d1fe23eabc4c98b48bffcef5a386062`
**Scope:** attention `*.scale` (F8_E8M0), `attn.compressor.wgate.weight` (BF16), `hc_head_*` (F32)

While running the shipped `inference/` reference kit against this checkpoint we
found three classes of tensors that cannot produce a working model as
distributed. All findings are **byte-identical between the HF repo and our
local partial download** (verified via HTTP Range requests against the exact
tensor byte spans), so this is not a download artifact.

### 1. Attention e8m0 scale tensors are noise-like

For a real 128×128-block FP8 quantizer, adjacent block scales are nearly
identical (smooth |Δbyte| ≈ 0–4). Measured on this checkpoint:

| tensor | adjacent \|Δbyte\| mean | median byte |
|---|---:|---:|
| `layers.2.attn.wkv.scale` | 87.2 | 119 |
| `layers.2.attn.wq_a.scale` | 77.8 | 130 |
| `layers.10.attn.wq_a.scale` | 79.4 | — |
| `layers.0.attn.wq_b.scale` | — | — |

Bytes span the full 0..255 range (including 0xFF in every layer; 1–5 blocks
per attention tensor). Dequantized under any ue8m0 interpretation
(2^(E−127), or the bit-insertion vLLM uses), implied weight magnitudes reach
2^60–2^124, which is not compatible with the e4m3 code distribution in the
paired weight tensors (codes are normal, amax 256–448, no NaNs).

### 2. Literal NaNs in bf16 `compressor.wgate`

* `layers.2.attn.compressor.wgate.weight` [1024, 4096]: **155 NaN entries**
* `layers.3.attn.compressor.wgate.weight` [512, 4096]: **178 NaN entries**

Spread across wgate tensors archive-wide (paired `wkv` tensors are clean).
SHA-256 (raw bf16 bytes):
`layers.2...wgate` `8d4242a05e2728f264bd32718bc8c4af…`,
`layers.3...wgate` `d0b512269f530613444d903ba6e1e59b…`.

### 3. `hc_head_*` fp32 tensors are non-credible

`hc_head_fn` / `hc_head_scale` contain values with std up to ~8e34 or are
entirely NaN — not plausibly trained weights.

### Loader behavior

The shipped `inference/generate.py` loads with `load_model(..., strict=False)`
and `inference/convert.py` performs no repair, so a run against these tensors
propagates NaN/garbage silently rather than erroring.

### Question

Are these tensors:
- intentional (some undocumented container/layout format),
- unused placeholders,
- corrupted during publication,
- expected to be regenerated by a procedure we missed,
- or superseded by another artifact (e.g. converted `model*-mp*.safetensors`)?

If they are corrupt, a corrected revision would unblock exact-parity
reproduction. Happy to provide the full census.

### Minimal reproducer (verification only, no model run needed)

```python
import torch, json, struct, requests
from safetensors import safe_open

REPO = "deepseek-ai/DeepSeek-V4-Flash-0731"
S = requests.Session()
idx = json.loads(S.get(f"https://huggingface.co/{REPO}/resolve/main/"
                       "model.safetensors.index.json", timeout=60).content)

def fetch(name):
    shard = idx["weight_map"][name]
    url = f"https://huggingface.co/{REPO}/resolve/main/{shard}"
    n = struct.unpack("<Q", S.get(url, headers={"Range": "bytes=0-7"},
                                  timeout=60).content)[0]
    hdr = json.loads(S.get(url, headers={"Range": f"bytes=8-{7+n}"},
                           timeout=120).content)
    off = hdr[name]["data_offsets"]
    return S.get(url, headers={"Range": f"bytes={off[0]}-{off[1]-1}"},
                 timeout=60).content

# 1) noise-like scales (compare with any locally block-quantized tensor)
raw = fetch("layers.2.attn.wkv.scale")
s = torch.frombuffer(bytearray(raw), dtype=torch.uint8).view(4, 32)
print("adjacent |dbyte| mean:",
      (s[:, 1:].int() - s[:, :-1].int()).abs().float().mean().item())  # ~87

# 2) NaNs in bf16 wgate
raw = fetch("layers.2.attn.compressor.wgate.weight")
w = torch.frombuffer(bytearray(raw), dtype=torch.bfloat16)
print("NaN count:", torch.isnan(w.float()).sum().item())               # 155
```
